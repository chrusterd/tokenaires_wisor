# 유저 시나리오 요약과 발표 구성 — Wisor

> 확인 시점 2026-09-08 · `apps/web`의 실제 라우트와 `lib/generated/scores.json`에서 읽은 값입니다.
> 전체 시나리오는 `docs/user-scenarios.md`에 있고, 이 문서는 **발표하기 위해 줄인 판**입니다.
> 숫자는 발표 당일 데이터로 다시 확인하세요 — 배치가 매일 `scores.json`을 갱신합니다.

---

## 1. 한 문장

**남이 고른 종목을 사던 사람이, 대가의 기준으로 직접 판정해 보고 "다음에 무엇을 확인할지"를 자기 말로 적게 만드는 서비스입니다.**

---

## 2. 유저 시나리오 — 네 줄

원문의 S1~S6을 사용자가 실제로 밟는 네 갈래로 묶었습니다. 넷 다 **확인 사항에서 끝나고, 사라는 말은 나오지 않습니다.**

| # | 누가 | 무엇이 답답해서 | 화면 순서 | 끝나는 지점 |
|---|---|---|---|---|
| **A. 뒤늦게 근거 찾기** | 추천을 따라 산 2~5년차 | 왜 샀는지 설명 못 한다 | 검색 → `/stocks/AAPL` → 기준 막대 → 해설 챗봇 → 학습노트 | 8개 기준 중 7개 판정·6개 충족·1개 `unknown`을 보고, 다음에 확인할 것을 한 줄 적는다 |
| **B. 기준으로 좁히기** | 자기 기준이 없는 사람 | 남의 목록만 있다 | `/screener/buffett` → 모델 전환 → 종목 → 관심종목 담기 | 왜 이 순서인지 보이는 관심종목 목록이 생긴다 |
| **C. 대가 한 명 통과하기** | 스터디·독서모임 | 책의 원칙이 손에 안 잡힌다 | `/learn` → 대가 → 5장(읽기 → 확인 → 정리) → `/learn` 하단 비교표 | 다섯 장 완료가 `/me`에 남는다. 종목 화면에 안 가도 완결된다 |
| **D. 며칠 뒤 돌아오기** | 전부 | 그때 뭘 확인하겠다고 했는지 잊었다 | `/me` → 진도·퀴즈·답변 이력 → 관심종목 → 노트 상태 변경 | 과거의 내 판단과 지금의 판단이 한 자리에 최신순으로 쌓인다 |

**세 줄로 더 줄이면** — 종목을 판정해 보고(A·B), 그 판정의 근거가 되는 철학을 배우고(C), 시간이 지나 자기 판단을 다시 본다(D).

### 화면 지도

```
/                     홈 — 원칙 · 일곱 대가 · 결과 미리보기
/learn                배우기 (+ 하단 철학 비교표)
  /masters/[slug]       대가별 경로 · 업적 · 출처
  /masters/[slug]/[1~5] 읽기 → 확인 문항 → 정리
  /scoring              점수가 어떻게 만들어지나
  /sources              커리큘럼 근거 자료
/screener/[style]     네 모델의 종목 결과
/stocks/[ticker]      기업별 판정 · 학습노트
/me                   진도 · 퀴즈 · 답변 이력 · 관심종목
PersonaChatFab        해설 챗봇 (전역, 어느 화면에서나)
```

## 3. 발표 구성 (10분 기준)

| 시간 | 무엇 | 목표 |
|---|---|---|
| 0:00–1:00 | 문제 | "왜 샀는지 말 못 한다"에 공감시키기 |
| 1:00–2:00 | 해법 한 문장 | 추천이 아니라 **판정과 기록** |
| 2:00–6:00 | **데모** | 시나리오 A → B → C → D를 한 흐름으로 |
| 6:00–8:00 | 어떻게 만들었나 | 데이터 · 점수 · 경계 |
| 8:00–9:00 | 안 만든 것 | 결정으로서의 미구현 |
| 9:00–10:00 | 다음 | 남은 작업과 질문 |

### 슬라이드별로 할 말

**① 문제 (1장)**
> "지난달에 산 종목, 왜 샀는지 한 문장으로 말할 수 있는 분 계신가요. 증권사 앱은 가격과 차트만 보여주고, 커뮤니티는 결론만 말합니다. 근거를 만드는 단계가 어디에도 없습니다."

**② 해법 (1장)**
> "Wisor는 종목을 추천하지 않습니다. 대가의 기준으로 **판정만** 보여주고, 사용자가 확인한 것을 학습노트로 모읍니다. 화면의 마지막 칸은 언제나 '다음에 무엇을 확인할지'이고, 그 칸은 비어 있습니다. 채우는 건 사용자입니다."

**③ 데모 (4분, 슬라이드 없이 화면)** — 클릭 순서를 그대로 따라갑니다.

1. `/stocks/AAPL` — "8개 기준 중 7개를 판정했고 6개를 충족했습니다. 이자 감당력은 데이터가 없어 `unknown`입니다. **없는 값을 0점으로 채우지 않고, 점수의 분모에서도 뺍니다.** 가격은 2026-08-24 종가, 재무는 2025-09-27 공시 기준입니다."
2. 우하단 해설 버튼 — "모르는 지표는 대가 페르소나가 설명합니다. 어느 화면에서나 뜹니다."
3. `/screener/buffett` — "379종목이 실려 있고, 그중 버핏 기준으로 채점된 건 312개입니다. 나머지는 **정보 부족**과 **모델이 맞지 않는 업종**으로 나눠 표시합니다. 억지로 점수를 만들지 않습니다."
4. 모델 전환 — "같은 기업을 그레이엄·린치·그린블랫으로 바꿔 보면 판정이 달라집니다. **어느 철학이 옳다고 말하지 않는 게 이 제품의 입장입니다.**"
5. `/learn/masters/graham/1` — "판정의 근거가 되는 철학은 일곱 명 × 다섯 장으로 배웁니다. 정답이 있는 문항만 채점하고, 생각을 묻는 문항은 점수 없이 기록만 남깁니다."
6. `/me` — "그 기록이 여기 쌓입니다. 같은 질문에 다시 답해도 예전 답이 남습니다. **과거의 내 판단과 지금의 판단을 나란히 보는 것**이 이 화면의 목적입니다."

**④ 어떻게 만들었나 (2장)**
> "S&P 500과 NASDAQ-100에서 중복을 뺀 517종목을 대상으로, SEC 공시와 토스증권 체결가로 매일 점수를 만듭니다. 품질 기준을 통과한 379종목이 화면에 실려 있습니다."
> "점수는 회귀식이 아니라 **기준 통과 여부의 가중 합**입니다. 임계값과 가중치가 화면에 그대로 나오고, `/learn/scoring`에서 전부 확인할 수 있습니다."
> "구조로 지키는 것 두 가지 — 재무데이터 전체는 브라우저로 나가지 않고, 사용자 데이터 저장은 파일 하나(`lib/store.ts`)를 거칩니다. 비회원은 브라우저에, 로그인하면 계정으로 병합됩니다."

**⑤ 안 만든 것 (1장)** — 발표에서 가장 반응이 좋은 자리입니다. 미완성이 아니라 결정으로 말합니다.
> "피셔·막스·소로스는 일부러 점수화하지 않았습니다. 공개 재무지표로 근사할 수 없는 철학이라, 자가진단 체크리스트로만 다룹니다. **점수화할 수 없는 것을 점수화하지 않는 것도 제품의 입장입니다.**"
> "빨강·초록을 쓰지 않습니다. 두 색은 가격 방향을 뜻하는데 이 제품은 방향을 말하지 않기 때문입니다."
> "'현재 기준'이라는 말을 쓰지 않습니다. 모든 화면에 가격 기준일과 재무 기준일이 함께 나갑니다."

**⑥ 다음 (1장)**
> "Supabase 원격 배포 마무리, 화면 안 종목 검색, 그리고 학습 → 판정 → 노트를 잇는 스모크 테스트가 남았습니다."

## 4. 예상 질문과 답

| 질문 | 답 |
|---|---|
| 추천 서비스와 뭐가 다릅니까 | 결론을 주지 않습니다. 판정 근거와 임계값을 다 열어 두고, 마지막 칸을 비워 둡니다 |
| 점수를 믿을 수 있습니까 | 믿으라고 하지 않습니다. `/learn/scoring`에 기준·임계값·가중치·`unknown` 처리가 전부 적혀 있습니다 |
| 데이터가 없는 기업은 | 미충족이 아니라 `unknown`입니다. `unknown`이 25%를 넘으면 점수를 만들지 않고 '정보 부족'으로 표시합니다 |
| 한국 주식은 | 아직 없습니다. 유니버스가 미국 두 지수입니다 |
| 수익률은 얼마나 나옵니까 | 성과를 약속하지 않습니다. 고르는 법을 가르치는 학습 서비스입니다 |
| 왜 대가가 일곱 명입니까 | 같은 다섯 장을 공유해야 비교가 되기 때문입니다. 그레이엄의 '처분'과 린치의 '처분'이 같은 자리에 있어야 합니다 |

## 5. 발표 전 점검

- [ ] 데모 당일 `scores.json`의 기준일로 대사의 날짜를 고칩니다 — "현재"라고 말하지 않습니다
- [ ] AAPL의 판정 개수가 그날도 7/6/1인지 확인합니다. 배치가 갱신하면 달라질 수 있습니다
- [ ] 해설 챗봇 서버가 깨어 있는지 미리 한 번 눌러 둡니다 (첫 요청이 느립니다)
- [ ] `/learn/compare`는 **누를 수 있는 링크가 없습니다.** 데모 경로에 넣지 말고, 비교표는 `/learn` 하단에서 보여 줍니다
- [ ] 화면에 '예시 데이터' 배지가 뜨면 실데이터가 덮인 것입니다 — 발표 전에 원인을 찾습니다
